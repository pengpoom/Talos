## When to Use
- **有实质科研进展时**：读懂一篇/一个方法、想通一个公式或思路、**否掉**一个方向、定了下一步。
- **科研 session 收尾**：陪读/精读/专注写作结束，记一句"今天科研到哪了"。
- 用户说"记一下：今天搞懂了 X / 这个思路不行 / 决定先做 Y"。

## 为什么要记（核心）
科研里很多是**"软"进展**（想通了、否了、决定了）——不落库，总管复盘和周报就**看不见**，只剩"读了几篇"的表象。研究日志把这些留痕，进**共享时间轴**，所以总管/周报都能读到。**这是软进展进入系统的唯一桥**。

## 怎么记
往共享时间轴追加一条，**打 `[研究]` 标签 + 一个类型**，一句话讲清：
```
research-assistant timeline-append --tz <tz> --text "[研究·读] ClawTrojan：把 prompt injection 推进到持久后门防御，关键是 DASGuard 监控 agent workspace 状态（arXiv 2605.31042）"
```
类型（放在 `[研究·X]`）：
- `读` —— 读懂了某篇/某方法（带出处/arXiv id）。
- `想通` —— 理解了某公式/思路/为什么 work。
- `否` —— 试过/想过但**否掉**的方向（**这条特别值钱**，省得以后重走）。
- `决定` —— 定了下一步做什么 / 选了哪条路。
- `卡` —— 卡在哪、缺什么（可顺手 `loops-add --domain research` 开个循环）。

**一条一句、带出处**。属于某项目就在文末标项目名，方便周报按项目拢。

## 与其他技能衔接
- 精读完（`paper-reader`）→ 顺手记一条 `[研究·读]`。
- 否掉/决定 → 记 `[研究·否]`/`[研究·决定]`；若变成待办，再 `loops-add --domain research`。
- 周报（`weekly-report`）/ 复盘（`evening-review`）会扫 `[研究]` 行拢成科研进展。

## Pitfalls
- **用 `[研究]` 前缀**，别和时间轴里的时段块（"09:00-10:00 写 intro"）混——前缀让它可筛。
- 一条一句，**带出处**（arXiv id / 论文节号），读不到不脑补。
- 别把每个琐碎念头都记；记**实质进展**（懂了/否了/定了/卡了）。

## Verification
- 读懂一篇 → 记 `[研究·读]` → 当天 `timeline/<date>.md` 多出带 `[研究]` 的一行。
- 周报触发 → 能从 `[研究]` 行拢出"本周读了 N 篇、想通 X、否了 Y"。
